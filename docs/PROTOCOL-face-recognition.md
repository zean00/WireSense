# Protocol: face recognition, vision context (pre-registered 2026-10-05)

Phase-4 vision work, under the standing constraint from the original
discussion: **local-only and opt-in, or not at all**. This protocol is
committed before any wiring or gate data, per house rules; numbers land
in the adjudication commits that follow. Component selection was
validated first (tools/probe_face.py — selection validation, not gate
data); routing reconnaissance used the current committed tree
(tools/probe_face_routing.py) to inform design decision 7.

## Component probe (selection validation, 2026-10-05)

YuNet detector (face_detection_yunet_2023mar.onnx, 232 KB) + SFace
embedder (face_recognition_sface_2021dec.onnx, 38.7 MB), both OpenCV Zoo,
Apache-2.0, CPU only — the GPU budget stays with the LLM (design
principle 1). Measured on three public-domain portraits
(tools/face_eval/imgs/, frozen as eval assets), at BOTH full resolution
and camera resolution (≤448 px JPEG q80 — the production frame budget
from the vision path):

- same-person cosine across hflip / jpeg-q30 / 10 % crop / scale-0.6 /
  cross-resolution: **min 0.881**
- different-person cosine across all portrait pairs and augmentation
  variants: **max 0.221**
- datasheet SFace cosine threshold 0.363 sits inside the gap; margin
  **0.661**
- latency: detect+embed **~11 ms** per frame on CPU

Probe iteration 1 measured cross-resolution cosine ~0.1 and an 0.853
different-person outlier — that was a probe bug (detector boxes in
downscaled coordinates fed to alignCrop on the original image), kept
here as the recorded reason detection and alignment share one
coordinate frame in decision 5. YuNet also misses oversized faces
(2 MP+ input, face large vs anchor stride): inputs are capped to a
640 px longest side before detection; production frames are ≤448 px
anyway.

## Registered design decisions

1. **Opt-in, off by default, local-only.** `web/config.json` gains a
   `face` block: `{"face": {"enabled": true}}`; absent block or false =
   disabled. Disabled means: no face code runs on any turn, the tool
   manifest omits both face tools, vision turns carry **no `face` key in
   metrics**, and enrollment attempts fall to the honest no-tool answer
   — byte-identical to pre-face behavior. Embeddings and names live in
   `web/faces.json` (gitignored — user biometric-derived data never
   enters git); raw frames are never persisted anywhere. Nothing ever
   leaves the machine: no cloud API at any layer.
2. **Recognition rides opted-in frames only.** Face processing runs only
   on frames the user's own request captured: vision turns
   (`request_frame`) and the enrollment frames. No ambient/background
   processing, no periodic grabbing, no processing of detect-tool
   frames beyond the detect request itself. Camera consent already
   belongs to the client; this adds a second gate, not a bypass.
3. **Component versions pinned.** YuNet 2023mar + SFace 2021dec in
   `models/face/` (gitignored, like every model weight). Dependency:
   `opencv-contrib-python-headless` (cv2.FaceDetectorYN /
   cv2.FaceRecognizerSF), CPU target.
4. **One coordinate frame, 640 px cap.** Detect on the capped image,
   alignCrop that same image (probe finding above).
5. **In-process module, off the event loop.** `web/faces.py`, called via
   `asyncio.to_thread` (measured ~11 ms; a sidecar would be ceremony).
   Models load lazily on first face-enabled use; a disabled server never
   touches cv2.
6. **Enrollment: tool-flow tool `face_enroll`.** Utterance lands in the
   tool flow; args `{name}` (1–40 chars). Server grabs up to 3 frames
   (~400 ms apart via existing `request_frame`), requires ≥2 detected
   faces, stores the renormalized mean of their embeddings per name.
   Re-enroll of an existing name overwrites (one entry per name).
   Confirmation sentence generated by the existing tool confirmation
   step; result notes frame quality on failure ("I couldn't see a face
   clearly — try again in better light").
7. **Forgetting: tool-flow tool `face_forget`.** Args `{name}` optional —
   with a name deletes that entry, without deletes all. "Forget
   everything you know about my face" is the blunt instrument.
8. **Recognition context, vision turns only.** When enabled AND at least
   one enrollment exists: on a vision turn with a frame, detect all
   faces, embed the up-to-3 largest, 1-NN cosine against all stored
   vectors. Match ≥ threshold → name; else "an unrecognized person".
   The result rides the volatile suffix as one context line —
   `(Camera: albert)` — inside the current turn's user message, never
   the frozen prefix, so the warm-KV discipline is untouched. No faces
   detected → no line. Metrics carry `face: {n, names[], ms}` on
   enabled vision turns; absent entirely when disabled.
9. **Threshold registered at 0.50.** Midpoint of the measured
   [0.221, 0.881] gap on the frozen portraits (geometric midpoint
   0.441; 0.50 leans toward stranger-rejection, the cost-asymmetric
   side — a false "that's albert" is worse than an unrecognized
   miss). Datasheet 0.363 sits below it and inside the gap.
10. **Multi-face.** Report up to 3 recognized/unrecognized persons in
    one context line ("Camera: albert and an unrecognized person").
    Enrollment uses the largest face in frame only.
11. **LLM sees names as context, not instructions.** The context line is
    sensory input; nothing in it changes directives. The model can be
    wrong about the person in prose — same failure class as vision
    itself.

Pre-registered plan: a think.tool pool top-up with enroll/forget-style
phrasings ("remember my face", "forget my face", "forget everything
about my face", "learn my face as X"-variants), tree version bump,
`make record-router`, then ALL existing frozen router bars re-run and
must hold (root frozen-56 subset ≥ 49/56, deep held-out 6/6, think
original ≥ 18/20, deep 5/6, followup ≥ 6/8, test-voice 11/11). If the
top-up cannot hold those bars after the same gate-loop discipline as
the deep work, ship WITHOUT it and record "forget-by-voice" as a
registered follow-up — no silent pool edits, per the detect precedent.
"Who am i" → direct is accepted for v1: without a vision turn there is
no frame, so identity context cannot exist; the honest direct answer is
correct behavior. A root-pool top-up for spoken identity queries is a
possible follow-up, not v1.

## Out of scope (v1), explicitly

- **Liveness / anti-spoofing.** A photo of an enrolled person shown to
  the camera will be recognized. Documented attack; mitigated only by
  the opt-in contract and physical-presence assumption. Any future
  liveness model is a new protocol.
- Recognition on non-vision turns; background/periodic camera use;
  video tracking across frames.
- Face verification UI, multi-user enrollment ceremonies, encryption
  at rest (gitignored file on a local disk is the v1 threat model,
  stated plainly).
- Emotion/attribute inference. Names only.

assets in tools/face_eval/imgs/):

- **G1 detection**: all 6 frozen renditions (3 portraits × full/cam)
  detect ≥ 1 face.
- **G2 same-person separation**: every same-person eval pair ≥ 0.50.
- **G3 stranger rejection**: every different-person pair < 0.50.
- **G4 recognition decision**: unit tests — match ≥ threshold names,
  below-threshold and empty-store return unrecognized/no-line;
  persistence round-trips; disabled config → manifest omits face
  tools, recognize() refuses.

Live (two registered runs of the existing harness):

  holds, plus the new "learn my face" case asserts the honest
  no-tool fallback and no `face` key in metrics.
- **G6 enabled run** (config flipped, `WIRESENSE_TEST_FACE=1 make
  test-voice`): enroll case stores albert (faces.json round-trips),
  re-enroll overwrites (still one entry), vision turn metrics carry
  `face.names == ["albert"]` on the einstein frame, forget empties
  the store, and the post-forget vision turn recognizes nobody.
- **G7 router gates** (only if the pool top-up shipped): all existing
  frozen bars hold, per the table above.
- **G8 no-regression**: eval-router numbers unchanged vs the v4
  adjudication if no tree edit; test-voice 11/11 (default run) always.
- **G9 latency**: `face.ms` p95 < 50 ms across enabled-run vision
  turns (budget against ~11 ms measured).

## Revision 1 (2026-10-05, during adjudication — documented, not silent)

The routing plan's pool top-up was measured through the full gate loop
and did not survive intact. Recorded so the next face/routing work
starts from evidence:

1. **4-ref think.tool top-up FAILED eval-followup** (rewrite 5/8 vs bar
   ≥ 6/8): the added refs rotated the tool centroid enough to flip
   "Update the parking location from level two to level three." from
   tool to long_think. A **minimal 3-ref top-up** ("Remember my face." /
   "Forget my face." / "Forget everything you know about my face.") holds
   every frozen bar and is what shipped.
2. **Root-pool top-up measured and rejected.** Adding "Remember my
   face." to the root think pool: the ref itself scored nearest
   **vision** (the "my face" content pull, 0.867, beat its own class),
   and the perturbed think centroid broke root direct ("Repeat that."
   crossed to think). Same lesson as the deep-think work: content beats
   cues; refs cannot overcome it at root without collateral damage.
3. **Design consequence — vision-branch intent gate.** Face-management
   phrasings route to **vision** at the root (arguably correct
   semantics: the user is talking about what the camera sees). When the
   feature is opted in, the vision branch intercepts them
   (FACE_INTENT_RE: remember/learn/save + face, forget/delete/erase +
   face) and runs the tool flow (face_intent) instead of a VLM query —
   same validate → run_tool → tool_call → confirmation plumbing as the
   manifest path. The gate is a fallback: mid-conversation, the fragment
   rewrite (≤4 words + non-empty history) rewrites "Forget my face."
   using context and the manifest path picks face_forget (measured,
   conf 0.611-0.631). The gate deterministically fires only with empty
   history — that is the e2e-tested path; both paths share all tool
   plumbing.
4. **Names are LLM/ASR-extracted and keep their casing** ("Learn my
   face as Albert." stores key `Albert`). Store and harness comparisons
   fold case; the confirmation sentence uses the extracted name.
5. **The eval-followup "coffee beans" miss (case 8) exists under the
   v4 refs too** — verified by A/B re-record. It is serving-numerics
   drift since the deep-think adjudication hours earlier, not a face
   change; recorded here because it surfaced in this gate loop. v4 refs
   today: followup 6/8 PASS (misses: dentist pool-coverage gap +
   coffee-beans drift). v5 = v4 + 3 subtree refs: same 6/8.
